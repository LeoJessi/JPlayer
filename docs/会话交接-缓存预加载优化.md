## 最新报错与修复

check.txt 最新内容记录了 2026-10-31 18:19:15 的进程崩溃：

    FATAL EXCEPTION: preload-scheduler
    java.lang.IllegalStateException: Unbalanced enter/exit
      at com.android.okhttp.okio.AsyncTimeout.enter(...)
      ...
      at java.io.BufferedInputStream.close(...)
      at ProxyCacheUtils.close(...)
      at HttpUrlSource.close(...)
      at HttpProxyCache.cancelRangePreload(...)
      at PreloadTask.cancel(...)
      at PreloadManager.computePreloadSpan(...)

根因是调度线程在尾部 Source 的读取线程仍处于 read() 时，直接调用 Source.close()；Android 的 OkHttp stream 不支持这种跨线程关闭顺序，触发 AsyncTimeout 状态异常。

本次修复让取消线程只向 Source 发取消信号；读取线程收到断连/取消后退出，并在自己的 finally 中关闭流。需重点验证的文件是 Source.java、HttpUrlSource.java、OkHttpSource.java、HttpProxyCache.java 和 PreloadTask.java。

## 日志结论

最新性能日志 check.txt（17:23–17:25）显示：

- 冷启动视频 159651 在播放开始时 cachedPrefix 为 0。播放器约 2 秒后请求偏移 8,908,269，代理选择 direct-upstream；头部 2MB 到播放后约 5.4 秒才完成。该视频的 MEDIA_PREPARED 约在播放后 11.4 秒。
- 159651 的尾部 Range 虽然覆盖播放器先前请求的 offset，但它在头部 2MB 完成后才启动，并且直到 MEDIA_PREPARED 之后才完成。缓存端顺序读取从 offset 0 读到源文件 EOF 与尾部任务完成时间几乎重合，说明尾部请求曾被同 URL 的顺序 SourceReader 阻塞。
- 159662 的尾部 Range 在播放前已完成，随后代理播放约 339ms 后 MEDIA_PREPARED。完全缓存后走 file:// 的样例约 15–26ms。样例不是相同视频的严格 A/B，不能把差值全部归为 HTTP 代理开销。
- “预加载 ready=true”只表示读到了预加载头部目标，不代表尾部 Range 已缓存，也不代表整个视频完整缓存。
- path=cache-backed 表示走缓存管道，不等于本次 Range 完全命中本地；需结合“源站读取完成”日志判断是否回源。

## 可避免的坑

- 修改独立 Range 时不可在调度线程调用 Source.close()；只发取消信号，让拥有输入流的 Range 线程负责 close。
- 不可用 .download.length() 判断连续头部缓存大小；尾部 sparse append 会把物理文件扩展到远端 offset，必须看区间 meta/FileCache.isCached()。
- 不可把 cache-backed 解释为“完全本地命中”；缓存管道可能会等待源站回源。
- 不可把 MEDIA_PREPARED 当成首帧指标；应同时看播放器 MEDIA_INFO_RENDERING_START 或实际首帧回调。
- 不要仅把头部预加载从 2MB 改成 1MB 来解决首播尾部 Range；最新日志中的关键请求在文件尾部。
- 不要因完整缓存测试得到 15–26ms 就推断局部预加载代理也能达到同等耗时；部分缓存缺失的数据仍必须从源站取回。
- 不要为了清理工作区而执行 git checkout、git reset 或删除未跟踪文件；当前存在多处未提交改动。
- git diff --check 若包含 check.txt，会报告其日志堆栈行的空格/Tab 格式；这是日志文本，不是 Java 文件错误。应对源码范围单独检查。

## 验收标准

- 独立尾部 Range 在获取总长度后尽早发起，不再等头部顺序下载到文件尾。
- 独立尾部 Range 写入同 URL 共享 FileCache 的稀疏区间，播放器随后请求该区间时不再打开源站 Range。
- 取消并发读取不会触发 AsyncTimeout Unbalanced enter/exit；取消后 Source 由读取线程关闭。
- 全缓存仍返回 file://；部分缓存继续使用代理，并能从缓存头部/尾部读取、缺失区间安全回源。
- 冷启动、缓存命中和首帧数据分开统计，不将 MEDIA_PREPARED 单独视为最终体验指标。
