- `PreloadSession.java`：提供当前会话 URL 查询，供缓冲取消逻辑保留当前项。

## 避免踩坑

- `127.0.0.1` 是设备内的代理入口；`cache-backed` 只表示经过缓存路径，不表示请求 Range 已经命中缓存。
- `cachedPrefix` 只代表从 0 开始的连续字节；尾部缓存是稀疏区间，不能用 `.download.length()` 判断是否命中。
- `ready=true` 只表示预加载目标头部字节已读满，不表示尾部 `moov` 或整个文件已缓存。
- 源站可能把一个 Range 206 响应限制在文件的一段；文件总长应优先取 `Content-Range` 的 `/total`，不能只用 `Content-Length + offset`。
- 取消时只发 `Source.cancel()`/断开连接信号；读取线程负责关闭它自己的输入流，避免跨线程关闭触发 Okio/`AsyncTimeout` 状态异常。
- 播放器切页时不要让缓冲回调取消当前 URL 的尾部 Range；远端未播放视频才是可取消的预加载。
- `MEDIA_PREPARED` 按用户确认作为首帧近似指标；本轮无需再用 `MEDIA_INFO_VIDEO_RENDERING_START` 替代它。
- 本次只修改 `HttpUrlSource` 默认源站实现，没有启用或切换 `OkHttpSource`。
- 不要用 `git checkout`、`git reset` 或清理未跟踪文件来“整理”工作区；保留当前所有未提交源码和用户日志。
