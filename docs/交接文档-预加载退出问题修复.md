# 预加载退出后仍在后台运行 - 问题修复交接文档

## 一、任务目标

**问题描述：** 用户在短剧播放页面（`ShortPlayActivity`）快速滑动后立即退出，预加载逻辑没有取消，仍在后台运行，持续消耗带宽并输出日志。

**期望行为：** "退出短剧播放页面"日志打印时（即 `Activity.onDestroy` 执行时），所有预加载任务应立即停止，代理端不再从上游源站读取数据。

## 四、卡点分析

### 当前状态
**用户反馈：修改后问题仍然存在，退出后还在预加载。**

### 日志分析（2026-11-03 19:44:18）
```
19:44:18.103 - "退出短剧播放页面"（onDestroy 执行）
19:44:18.117 - Shutdown proxy for 159654.mp4（代理关闭）
19:44:18.118 - Request to cache proxy:...159657.mp4（新代理请求！）
19:44:18.155 - Request to cache proxy:...159658.mp4（新代理请求！）
19:44:22.741 - Accept new socket（新 socket 连接！）
```

**关键发现：** 退出后 15ms 就有新的代理请求，说明 `PreloadTask` 在 `onDestroy` 之后才出队执行。

### 可能的根本原因

#### 原因 1：`PreloadTask.run()` 只检查一次 `mIsCanceled`
```java
public void run() {
    if (!mIsCanceled) {  // 只检查一次！
        bytes = start();  // 如果任务在这里面耗时，cancel 无法打断
    }
}
```
**分析：** 如果任务在 `mWorkerPool` 队列中排队，`cancel()` 会设置 `mIsCanceled=true`，但任务出队后 `run()` 检查 `mIsCanceled` 为 true，会跳过 `start()`。**但是**，如果任务在 `cancel()` 之前就已经开始执行 `start()`，那么 `start()` 中的 `openConnection()` 无法被打断。

**已尝试修复：** 在 `start()` 方法中增加了两个取消检查点（方法开头 + `getProxyUrl` 之前）。

#### 原因 2：`HttpProxyCacheServer` 的代理端仍在运行
**分析：** `PreloadTask.cancel()` 调用 `mCacheServer.cancelPreload(mRawUrl)`，但代理端的 `processSocket` 线程可能仍在运行，继续从上游源站读取数据。

**已尝试修复：** 在 `HttpProxyCache.responseWithoutCache()` 和 `responseWithCache()` 循环中增加 `mCanceled` 检查。

#### 原因 3：`PreloadSession.onDestroy()` 没有被正确调用
**分析：** 需要确认 `PreloadSession` 是否正确绑定到 `Activity` 的生命周期，`onDestroy()` 是否被调用。

**验证方法：** 在 `onDestroy()` 中增加日志，确认是否被调用。

## 六、可以避免的坑

### 坑 1：不要在 `cancelPreload()` 中调用 `source.close()`
**问题：** `source.close()` 可能导致 `Unbalanced enter/exit` 崩溃。
**原因：** `source` 可能正在被其他线程使用，OkHttp 的 `AsyncTimeout` 不支持跨线程关闭。
**解决方案：** 只设置 `mCanceled` 标志，让 `source` 的拥有者通过 `finally` 块关闭。

### 坑 2：不要使用 `cancelAllTasks()`
**问题：** 会取消所有会话的任务，导致其他页面重新提交任务，造成额外网络请求。
**解决方案：** 使用 `cancelTasksForSession()` 只取消当前会话的任务。

### 坑 3：`PreloadTask.run()` 只检查一次 `mIsCanceled`
**问题：** 如果任务在 `cancel()` 之前就已经开始执行 `start()`，那么 `start()` 中的 `openConnection()` 无法被打断。
**解决方案：** 在 `start()` 方法中增加多个取消检查点。

### 坑 4：`PreloadSession.onDestroy()` 中缺少 `unregisterSession()`
**问题：** 会话残留在 `mSessions` 中，导致内存泄漏。
**解决方案：** 确保 `onDestroy()` 中调用了 `mManager.unregisterSession(this)`。

### 坑 5：跨线程关闭 `HttpURLConnection`
**问题：** `connection.disconnect()` 可能导致 `Unbalanced enter/exit` 崩溃。
**解决方案：** 避免在 `cancel()` 中调用 `connection.disconnect()`，让 `start()` 的 `finally` 块处理。
